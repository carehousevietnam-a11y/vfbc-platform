1. 과거 자산 금지: 행정문서 Admin MASTER 이외의 과거 자산(옛 부동산 엔진·번역표·페이지·테스트 결과물·폐기 초안·archive 브랜치)은 import·복사·참조·인용하지 않는다. 폐기는 새 페이지 완성 후 Ace 지시로 한꺼번에 한다.
2. Admin MASTER 읽기 전용: Admin 파일은 수정·복제·재구성하지 않는다. import 로만 쓴다. 기본으로 삼되 계속 바꾸는 행위를 하지 않는다.
3. UI 동일성: 디자인, 편집(콘텐츠 배치), 정렬, 간격, 글자, 색, 버튼, 진행 표시, 카드, 모바일 동작이 행정문서 MASTER 와 동일하다. 다른 점은 Content Pack 이 만드는 문구뿐이다. 새 UI 컴포넌트·임의 스타일을 만들지 않는다. 모든 화면 단계(Q1, 1차 질문, 간단 자료, 회원, 1차 결과, 2차 질문, 2차 자료, My Page, PDF)에서 Admin 과 나란히 비교한 표를 보고한다. 구현은 Admin 과 같은 부품에 Pack 내용만 주입한다. 비슷한 신규 화면을 조립하지 않는다. 공용 컴포넌트의 서비스별 prop(domain 등)으로 레이아웃이 갈리면 그 경로를 쓰지 않는다.
4. 질문·선택지·표현 품질: PASS 1순위는 "해당 분야 전문가가 실제 상담에서 묻는 질문인가". 질문은 사실을 확보하고, Situation Profile 필드에 매핑되고, 다음 질문을 바꾸고, 결과에 영향을 준다. 선택지는 상황+관계+상태+행동을 담은 구조화된 사실. 법적 조건은 법적 결론이 아닌 사실로 묻는다. 외국인 고객 친화 표현을 쓰되 정보 밀도는 유지한다.
5. 같은 Value = 같은 Meaning: 선택 → 저장 → 요약 → 재방문 → 결과 → My Page → PDF 전 구간에서 value 의 의미가 같다. value 는 전역 유일하다. 하나의 단일 표(value → label → meaning)가 출처다.
6. 엔진·콘텐츠 분리: 공용 엔진(src/lib/contentPacks/engine/)에는 서비스 식별자가 0건이다. 서비스 전용 요소는 해당 서비스 폴더에만 둔다. 새 서비스는 Content Pack 만 새로 써서 같은 엔진으로 돌린다.
7. 문장은 원문 단일 출처: 결과·STEP·질문·선택지 문장은 Content Pack 문서에서 파싱한 데이터에서만 온다. 코드 보조 맵·요약·말줄임·폴백 문장 금지. 문서가 모호하거나 틀리면 수정하지 말고 목록으로 보고한다.
8. 검증은 전수: fixture 1건 통과를 PASS 로 쓰지 않는다. 전 PATH·전 CASE·전 단계 통과만 PASS. NOT VERIFIED 가 있으면 미완으로 보고한다.
9. 범위 준수: 지시받은 화면·범위만 건드린다. 확장은 Ace 에게 먼저 묻는다. 공용 파일(레지스트리, 공용 컴포넌트, 설정)은 변경 0 이 기본이다.
10. 속도와 학습: 불확실하면 한 줄 보고 후 가능한 부분을 계속한다. 문제가 하나라도 생기면 CLEAN_BUILD_LESSONS.md 에 한 줄 추가하고 보고서 "신규 교훈" 에 적는다.
11. 커밋·push 는 Ace 승인 후에만 한다. 테스트 데이터(lead)는 삭제하지 않는다.
12. 순차 실행: tsc, build, 대량 테스트는 병렬로 돌리지 않는다. 빌드 전에 .next 를 비운다.
13. 금칙어 0, 담당 표기는 "VFBCAI 전문가팀" 만 쓰고 실명 금지, 수수료는 ○○○ 로 가린다.
14. 마스터 우선순위
- Admin 수정은 서비스 중립 슬롯 추가에 한하며 /verify/admin 렌더 불변 증명 필수(2026-10-07 대표 승인, 1회).
- 모든 신규 서비스의 기준은 행정문서(Admin) 마스터의 "최종 확정본·가장 최근 것"이다. 과거 자료·구 버전·복구·회귀는 기준이 될 수 없고 끌어오지 않는다.
- 질문/선택/표현의 밀도, 파일 업로드, 결과 페이지, 마이페이지, AI 리포트의 UI 디자인·구조·편집·정렬은 Admin과 100% 동일하다. 서비스마다 다른 것은 Content Pack의 내용·맥락·값·목록뿐이다.
- 구현 방식은 "Admin과 같은 부품 + 내용 주입"이다. 새로 비슷하게 조립하지 않는다.
- 같은 오류가 반복되면 부분 수정을 반복하지 말고, 해당 서비스 전 단계를 Admin과 한 번에 대조해 구조 차이를 모두 찾는다.
15. 내용 기준
- 각 서비스의 내용은 해당 분야 전문가가 실제 상담에서 묻는 질문과 맥락으로 프로파일링한다. 세계 최고 전문가 수준의 내용 축적을 목표로 한다.
- 베트남어를 전혀 모르는 사람도 이해할 수 있게 쓴다. 사용자의 상황이 추적되어 질문→선택→요약→재방문→결과→마이페이지→PDF까지 같은 값이 같은 의미로 이어진다(독자 VFBCAI 데이터 구축).
