# VFBCAI 고정 컨텍스트 — 확정 사항 (해석·재설계·재제안 금지)
■ 0. 이 문서의 사용 규칙 (모든 AI 도구 공통: ChatGPT / Claude / Cursor)
- 이 문서의 내용은 모두 이미 결정·LOCK된 사항이다. 다시 묻거나, 대안을 제안하거나, "더 나은 구조"를 제시하지 않는다.
- 요청 범위 밖의 화면·구조·흐름·DB·UI를 언급하거나 수정하지 않는다.
- 이 문서와 충돌하는 판단이 필요하면 임의로 결정하지 않는다. "충돌 항목: ○○"으로 표시하고 멈춘다.
- 이 문서를 수정할 수 있는 사람은 대표(Ace)뿐이다.
■ 1. 프로젝트 개요
- VFBCAI(베트남 외국인 비즈니스 검증·등록 AI 센터), vfbcai.com
- 대상: 베트남에서 법률·행정 절차를 처리해야 하는 외국인(주로 한국인). 베트남어를 몰라도 이해할 수 있어야 한다.
- 4개 축: CHECK(자격/비용/서류/절차 확인) / VERIFY(계약·부동산·세무·사기 검토) / REGISTER(인허가 등록대행) / PROTECT(만료일·서류 사후관리)
- 기술: Next.js / TypeScript / Supabase / OpenAI / Vercel
■ 2. 역할 분담 (고정)
- 대표(Ace): 기획·승인·최종 결정
- Claude: 분석, 검토(브라우저 점검 포함), Cursor 지시서 작성, Cursor 결과 검토
- Cursor: 구현, 자체 QA, DB/Storage 읽기 검증, git commit
- ChatGPT: 콘텐츠 원문 작성 + MASTER 기준 점검 + 범위 통제. 배치당 1회만 관여.
- ChatGPT는 코드·구현 방식·화면 설계를 지시하지 않는다.
■ 3. 확정·LOCK 사항 (수정 금지)
- 행정문서(Admin) VERIFY = MASTER. 질문/선택지/표현, 1차·2차 업로드, 1차 결과, 회원가입 모두 완료·동결.
- Admin MASTER는 읽기 전용 기준이다. 수정·재작업하지 않고 import만 한다.
- 고객 퍼널(확정):
  Situation Profile(내부 추적용, 고객에게 비노출)
  → 적응형 MASTER 질문(Stop Condition 충족 시 종료)
  → 회원가입 1회(결과 직전)
  → 결과
  → 무료: 1차 결과 → 마이페이지("전문가 진행하기" 버튼)
  → 유료: 2차 개인화 질문 + 상세 자료 업로드 → "종합 결과 보기" → 마이페이지(간단 결과 + "AI 리포트 보기" + "전문가 진행하기")
- "전문가 진행하기"는 결제 화면으로 바로 보내지 않는다. 전문가 페이지에서 2차 질문·서류 제출만 활성화되고, 유료 기능은 결제 후 열린다(결제는 별도 미션).
- 선택지 밀도: 질문당 4~5개 + 직접입력. 단순 Yes/No 금지. 실제 상황을 구분하는 선택지로 만든다.
- 결과 구성 방향: 공통 40% / 개인화 60%
- V1 범위: 통제 가능한 적응형 시스템(검증된 질문 라이브러리 + 명확한 분기 규칙 + Stop Condition). AI 완전 자동 분류는 V2.
- 일반적인 케이스는 퍼널이 끝까지 처리하고, 특수·복잡 케이스는 "전문가 진행"으로 보낸다.
■ 4. 빌드 원칙 (Clean Build)
- 엔진 1개(Admin MASTER) + 서비스별 Content Pack을 새로 작성한다.
- 기존 서비스 코드·구 엔진·번역표·옛 페이지·폐기된 초안은 절대 가져오지 않는다.
- "내용만 다르다"의 의미: 프레임워크(프로파일링, 질문·선택지·표현 밀도 규칙, 흐름)는 그대로 쓰되, 각 서비스의 문맥과 문장은 해당 도메인에 맞게 새로 쓴다. 행정문서 문장에서 단어만 바꾸는 방식은 금지한다.
- 같은 값 = 같은 의미/라벨: 선택 → 저장 → 요약 → 재방문 → 결과 → 마이페이지 전 구간에서 일치해야 한다.
- UI·편집·정렬은 Admin MASTER와 처음부터 동일하게 한다.
- 지정된 서비스 화면 외에는 수정하지 않는다(확정된 마이페이지 등 포함).
- 레거시 코드는 새 서비스가 LOCK된 뒤 일괄 삭제한다.
- 빌드 중 발생한 문제는 크기와 관계없이 lessons ledger에 누적하고, 다음 구현에 반영한다.
■ 5. 현재 진행 상태 (2026-10-08 기준)
- 행정문서(Admin): 완료·LOCK
- 부동산 VERIFY: Clean Build로 콘텐츠 완료
- 다음: 사기 → 세금 → 기타/불명확
  (10/7 결정: 부동산 이후 나머지 VERIFY 서비스는 Cursor 별도 창에서 병렬 빌드하고, 대표가 일괄 검토한다)
■ 6. 사기(Fraud) VERIFY 콘텐츠 필수 요구사항
① 첫 분기: "피해 전 검증"(송금·계약 전에 상대를 확인) vs "피해 후 대응"(이미 송금·손해 발생). 두 경로는 질문 흐름을 분리한다.
② 긴급 Stop Condition: "지금 송금 요청을 받는 중" 또는 "송금 후 72시간 이내"이면 추가 질문 없이 즉시 행동 안내(은행 지급정지 요청, 공안 신고)를 제시하고 전문가 진행으로 연결한다.
③ Situation Profile 필드 후보: 사기 유형(투자·동업 / 취업·비자 대행 / 임대 보증금 / 온라인·메신저 / 공공기관 사칭) · 진행 단계 · 금액대 · 지급 수단(베트남 계좌 이체·현금·코인 등) · 보유 증거(계약서·채팅·영수증 등) · 상대 신원 확인 수준(개인/법인, 사업자번호 유무) · 신고 여부 · 고객 목표(송금 차단·회수·신고·상대 검증)
④ 타 서비스 경계 라우팅: 임대 보증금 사기 ↔ 부동산, 공안·세무서 사칭 ↔ 행정문서. 어느 쪽으로 보낼지 규칙으로 명시한다.
⑤ 결과 문장은 "사기입니다"처럼 단정하지 않는다. "위험 신호 N개 확인" 같은 신호 기반 표현을 쓴다.
⑥ 전문가가 실제로 판단할 수 있는 핵심 정보가 프로파일에 남아야 한다.
■ 7. 금지 사항
- LOCK된 Admin/부동산 구조·문구 수정 금지
- 요청 없는 새 화면, 새 퍼널 단계, 새 결제 흐름 추가 금지
- 레거시 서비스 페이지 내용 참고·인용 금지
- 범위를 넓혀야 할 때는 대표에게 먼저 묻는다
