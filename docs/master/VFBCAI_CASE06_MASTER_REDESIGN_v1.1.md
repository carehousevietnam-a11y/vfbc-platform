# VFBCAI CASE_06 (불명확 문서) MASTER 재설계 v1.1

**v1.1 변경사항 (STEP2-0 보충 조사 반영):**
- 체인③ Q2~Q6에 누락되어 있던 선택지 문구를 추가함 (v1.0 결함 수정)
- 체인④ Q1 Profile 필드명을 `case06_dispositionType` → `case06_dispositionTypeCandidate`로 변경
  (CASE_05의 `case05_dispositionType`과 동명이사 충돌 방지)

CASE_06은 "무슨 문서인지 모르겠다"는 사용자를 위한 Bridge/Reclassification CASE다.
Phase1은 쉽고 빠른 골격 파악(고정 5문항), Phase2는 Phase1 Q1의 후보값에 따라
완전히 다른 "전용 사건 재구성 체인"으로 들어간다. 질문 수는 고정하지 않되,
선택지는 항상 최대 5개(내용) + Direct Input 1개로 제한한다.

핵심 판정 기준: "이 질문 + 선택지로 전문가가 다음에 물을 필요가 있는 사실까지
구조화했는가?" STOP은 게이트 충족이 아니라 "전문가가 더 물을 의미가 없을 때"다.

## Phase1 (고정 5문항)

### P1-Q1 [요구행위 — 재분류 후보, 확정 아님]
**질문:** "문서에서 실제로 하라고 적혀 있거나, 상대방에게 설명받은 내용은 무엇인가요?"
1. 돈을 내라고 했습니다 (벌금·과태료·비용 등)
2. 어디로 가거나 출석해서 설명하라고 했습니다
3. 서류를 제출하거나 빠진 내용을 보완하라고 했습니다
4. 이미 내려진 처분이나 제재를 통보받았습니다
5. 문제·위반이 있다고 했지만 무엇을 해야 하는지는 정확히 모릅니다
**DI:** 위에 내용이 없거나 설명이 필요합니다 → 직접 입력
**Profile:** `case06_requiredActionCandidate` (candidate, 확정 아님)
**Branch:** 1→돈 체인, 2→출석 체인, 3→서류보완 체인, 4→처분 체인, 5/DI→불명확 체인

### P1-Q2 [정보 습득 경로]
**질문:** "이 내용을 실제로 어떻게 확인하셨나요?"
1. 문서를 직접 확인했고, 적힌 내용을 어느 정도 이해하고 있습니다
2. 문서는 직접 봤지만, 무슨 뜻인지 정확히 이해하지 못했습니다
3. 문서는 보지 못했고, 기관이나 다른 사람이 설명해 주었습니다
4. 문서가 있었지만 지금은 확인할 수 없어서 기억나는 내용만 압니다
5. 문서를 봤는지 누구에게 들었는지 등 경로가 불분명합니다
**DI:** 직접 입력
**Profile:** `case06_knowledgeSource`

### P1-Q3 [발신 경로]
**질문:** "이 내용은 어디에서 어떻게 전달받으셨나요?"
1. 정부기관에서 받은 문서·공식 안내를 직접 확인했습니다
2. 정부기관에서 전화·문자·방문 등으로 직접 안내받았습니다
3. 회사·중개인·대리인이 기관 내용을 전달했습니다
4. 지인이 기관에서 들은 내용을 다시 설명해 주었습니다
5. 어느 기관·누구에게서 나온 내용인지 알 수 없습니다
**DI:** 직접 입력
**Profile:** `case06_sourceChannel`

### P1-Q4 [행위+기한 결합]
**질문:** "기관에서는 언제까지 무엇을 하라고 안내했나요?"
1. 특정 날짜까지 돈을 내라고 안내했습니다
2. 특정 날짜까지 서류 제출·보완을 안내했습니다
3. 특정 날짜에 출석·설명을 안내했습니다
4. 해야 할 일은 있으나 언제·무엇인지 정확히 모릅니다
5. 기한 안내 자체를 받은 적이 없습니다
**DI:** 직접 입력
**Profile:** `case06_deadlineActionPair`

### P1-Q5 [현재까지의 대응]
**질문:** "그 안내를 받은 뒤 지금까지 실제로 어떻게 대응하셨나요?"
1. 아직 아무 대응도 하지 않았습니다
2. 기관에 문의·재확인했습니다
3. 요구받은 서류·자료를 준비·제출했습니다
4. 돈을 납부했거나 납부하려 했습니다
5. 출석·설명했지만, 그 뒤 다시 안내·보완·추가 요구를 받았습니다
**DI:** 직접 입력
**Profile:** `case06_customerResponse`

## Phase2 — 후보별 전용 재구성 체인

공통 원칙: Phase1에서 이미 확보된 정보(knowledgeSource, sourceChannel,
deadlineActionPair, customerResponse)는 재질문하지 않는다. 목표(goal)는
6번째 고정 질문으로 넣지 않고, 재분류된 target CASE 쪽에서 필요하면 묻는다.

### ① 돈 요구 (candidate=1) → CASE_02 후보

1. "무엇에 대한 비용이라고 안내받았나요?" — 위반·과태료 / 신청·허가 수수료 / 기존 발생 비용(세금 등) / 설명 못 받음 + DI → `case06_paymentNature`
2. "얼마를 내라고 안내받았나요?" — 정확한 금액 앎 / 대략만 앎 / 여러 번 다르게 안내됨 / 아직 안내 못 받음 + DI → `case06_paymentAmountKnown`
3. "그 금액이 실제 본인 상황과 맞다고 생각하시나요?" — 맞음 / 금액·사유가 실제와 다름 / 판단 정보 부족 / 이미 낸 적 있는데 재요구 + DI → `case06_paymentSituationMatch`
4. "기관에 직접 확인해 보셨나요?" — 확인해서 명확한 답 받음 / 확인했지만 불명확 / 아직 확인 안 함 / 연락 안 됨 + DI → `case06_paymentAuthorityCheck`
5. "지금까지 실제로 어떻게 하셨나요?" — 이미 납부 / 납부 준비 중 / 이의제기·재확인 요청 / 아무것도 안 함 + DI → `case06_paymentResponse`
6. (미납 상태일 때만, 조건부) "기한 내 내지 않으면 어떻게 된다고 안내받았나요?" — 제재·강제징수 안내 / 이자·가산금 안내 / 안내 못 받음 + DI → `case06_paymentNonPaymentNotice`

**STOP:** 위 6개 항목이 확보되면 → CASE_02 재분류

### ② 출석·소명 요구 (candidate=2) → CASE_03 후보

1. "무엇에 대해 출석하거나 설명하라고 했나요?" — 특정 위반행위 설명 / 제출서류·신청내용 확인 / 진행 중 사안 추가조사 / 설명 못 받음 + DI → `case06_attendanceSubject`
2. "기관이 문제 삼는 내용이 실제 상황과 맞다고 생각하시나요?" — 맞음(실제 있었음) / 일부만 맞음 / 전혀 다름 / 판단 정보 부족 + DI → `case06_attendanceFactMatch`
3. "언제, 어디서, 어떤 방식으로 통지받았나요?" — 정확한 날짜·장소·방식 앎 / 대략 시기만 앎 / 통지 방식만 기억 / 기억 안 남 + DI → `case06_attendanceNoticeDetail`
4. "지금까지 실제로 어떻게 대응하셨나요?" — 이미 출석·설명함 / 서류·자료 제출함 / 아직 대응 안 함 / 방법 몰라 못 함 + DI → `case06_attendanceResponse`
5. (이미 대응한 경우만, 조건부) "대응 이후 기관은 어떻게 반응했나요?" — 문제없다는 답변 / 추가자료·재출석 재요구 / 아직 답변 없음 / 오히려 불리한 통보 + DI → `case06_attendanceAuthorityReaction`

**STOP:** 위 항목이 확보되면 → CASE_03 재분류

### ③ 서류 제출/보완 (candidate=3) → CASE_04 후보

1. "기관에서는 어떤 서류나 내용을 다시 제출·보완하라고 했나요?" — 빠진 서류 추가 제출 / 기존 서류 잘못된 내용 수정 / 번역·인증 재요구 / 추가 설명·증빙 자료 / 설명 못 받음 + DI → `case06_submissionRequirement`
2. "그 보완을 요구받은 이유를 기관에서는 어떻게 설명했나요?" — 신청 요건 자체가 원래 부족했다고 설명함 / 제출한 서류에 오류·불일치가 있다고 설명함 / 정책·규정이 바뀌어서 추가로 필요하다고 설명함 / 이유를 구체적으로 설명받지 못함 + DI → `case06_submissionReason`
3. "그 설명이 실제 본인 상황과 어떻게 연결된다고 알고 계신가요?" — 맞습니다(실제로 그 요건·서류가 부족했거나 잘못되었습니다) / 일부만 맞습니다(지적된 것 중 일부만 실제 문제입니다) / 전혀 다릅니다(이미 제출했거나 문제가 없던 내용입니다) / 판단할 정보가 부족합니다 + DI → `case06_submissionRelation`
4. "안내를 받은 뒤 실제로 무엇을 제출·설명하셨나요?" — 요구받은 서류를 모두 준비해서 제출했습니다 / 일부만 준비해서 제출했습니다 / 아직 아무것도 제출하지 않았습니다 / 무엇을 어떻게 제출해야 할지 몰라서 못했습니다 + DI → `case06_submissionResponse`
5. "그 후 기관에서는 어떻게 답변하거나 다시 요구했나요?" — 문제없다는 답변을 받았습니다 / 추가 서류·보완을 다시 요구받았습니다 / 아직 답변을 받지 못했습니다 / 오히려 불리한 통보(반려·거부 등)를 받았습니다 + DI → `case06_submissionAuthorityReaction`
6. (조건부: Q4 `case06_submissionResponse`가 "아직 아무것도 제출하지 않았습니다"가 아닌 경우에만 노출) "현재 가지고 있는 자료 중 이 내용을 확인할 수 있는 것은 무엇인가요?" — 원본 서류·사본을 가지고 있습니다 / 기관과 주고받은 문자·이메일·메모가 있습니다 / 담당자와 통화·상담한 기록이 있습니다 / 확인할 수 있는 자료가 없습니다 + DI → `case06_submissionEvidence`

**STOP:** 위 정보가 확보되면 → CASE_04 재분류

### ④ 처분·제재 통보 (candidate=4) → CASE_05 후보

1. "어떤 처분이라고 안내받았나요?" — 영업·업무정지 / 허가·등록 취소 / 벌금형 처분 / 명칭은 모르고 안 좋은 조치라는 것만 앎 + DI → `case06_dispositionTypeCandidate`
2. "그 처분의 이유를 기관에서는 어떻게 설명했나요?" — 특정 위반행위 때문 / 서류·요건 미비 때문 / 들었지만 이해 못함 / 설명 못 받음 + DI → `case06_dispositionReason`
3. "그 이유가 실제 본인 상황과 맞다고 생각하시나요?" — 맞음 / 일부만 맞음 / 전혀 다름 / 판단 정보 부족 + DI → `case06_dispositionFactMatch`
4. "이 처분은 언제부터 효력이 생긴다고 안내받았나요?" — 정확한 발효일 앎 / 대략 시기만 앎 / 이미 효력 시작됐다고 들음 / 안내 못 받음 + DI → `case06_dispositionEffectiveDate`
5. "지금까지 실제로 어떻게 대응하셨나요?" — 이의신청·재검토 요청 / 요구자료 제출 / 아무것도 안 함 / 이의제기 방법조차 모름 + DI → `case06_dispositionResponse`

**STOP:** 위 정보가 확보되면 → CASE_05 재분류

### ⑤ 여전히 불명확 (candidate=5 또는 DI) → CASE_01 후보 또는 전문가 확인

1. (재확인) "그 문서나 안내에서 기관이 실제로 언급한 내용은 무엇인가요?" — 위반·문제 언급 / 돈 관련 언급 / 서류·제출 관련 언급 / 출석·설명 요구 언급 / 이미 결정된 조치 언급 + DI(기억도 안 남) → `case06_unclearContentRecheck`
2. "기관이 지적한 내용이 실제 본인 상황과 어떤 관계가 있다고 생각하시나요?" — 실제 있었음 / 일부만 관련 / 전혀 무관 / 판단 정보 없음 + DI → `case06_unclearFactRelation`
3. "지금까지 이 건에 대해 실제로 무엇을 하셨나요?" — 기관에 문의 / 서류·자료 준비 / 아무것도 안 함 / 뭘 해야 할지 몰라 못 함 + DI → `case06_unclearResponse`

**STOP:**
- 1번 재확인에서 1~5 신호가 잡히면 → 해당 CASE로 재분류
- 1번도 다시 DI(여전히 불명확)면 → **전문가 확인 필요로 종료**, Profile에 다음을 기록:
  - `case06_classificationStatus = "unresolved"`
  - `case06_unresolvedReason = "document_action_nature_unclear"`
  - `case06_expertHandoffRequired = true`

## 재분류 시 원칙 (모든 후보 공통)

1. Q1의 후보값은 **확정이 아니다.** target CASE 진입 후 최소 1개 이상의 "값-질문"
   (예: CASE_02의 실제 금액, CASE_05의 실제 처분 유형)에 대한 답이 Q1 후보와
   모순되지 않아야 최종 확정된다.
2. CASE_06에서 확보한 정보는 **상태 정보**(예: "금액을 대략 알고 있음")이지
   **실제 값**(정확한 금액)이 아니다. target CASE의 값-질문은 스킵하지 않는다.
3. target CASE에 이미 있는 동일 축의 상태 질문(예: 발신기관 인지 여부)은
   중복 질문하지 않고 CASE_06 Phase1/Phase2 답변을 그대로 이관한다.

## 옵션 개수 규칙

모든 질문은 내용 선택지 최대 5개 + Direct Input 1개. Direct Input은 항상
"위에 내용이 없거나 설명이 필요합니다 → 직접 입력" 형태의 정식 데이터 입력
경로이며 "기타"가 아니다.
