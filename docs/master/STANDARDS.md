# VFBCAI 확정 기준 (단일 출처)

이 문서는 저장소 마스터 문서에 이미 적힌 상시 기준과 대표(Ace) 지시를 모은 것이다. 새로 만든 규칙이 아니다. 항목마다 출처를 적었다. 원문과 다르게 해석하지 않는다. 변경은 맨 끝의 절차만 따른다.
모든 작업은 시작 전에 이 문서, QUESTION_STANDARD.md, LESSONS.md, HARNESS.md를 읽고, 보고 첫 줄에 `읽음: 파일명들`을 적는다.

## 우선순위

- P1 과거 문서와 현재 문서가 충돌하면 가장 최근 것이 우선한다. 예외 없다. (VFBCAI_QUESTION_CHOICE_RULE_LOCK_FINAL.md §0)
- P2 구현자·검토자는 확정된 규칙을 다시 대표에게 확인받지 않는다. 적용 책임은 구현·검토 측에 있다. (같은 문서 §0)
- P3 대표가 대화에서 새로 말한 규칙은 위 문서들보다 새롭다. 아래 "대표 지시"가 그 기록이며 해당 항목은 옛 문서보다 우선한다.

## 대표 지시 (최근, 옛 문서보다 우선)

- A1 질문은 한 문장 안에 두 가지를 묻는다. 선택지는 "굵은 요점 + 설명 문장"이고, 한 선택이 저장하는 필드는 정확히 2개(질문의 앞부분·뒷부분 대응)다. 한 질문에서 여러 개의 양질의 정보를 얻는 것이 이 사업의 핵심이다. 세부는 QUESTION_STANDARD.md. (대표 지시 2026-10-11)
- A2 질문 개수와 선택지 개수는 고정하지 않는다. 서비스에 따라 더 필요할 수 있다. 선택지는 4개 이상 + 직접 입력이며 상한을 두지 않는다. 이 항목은 선택지 최대 5개 규칙(VFBCAI_QUESTION_CHOICE_MAX_FIVE_RULE_v1_1.md, 2026-09-26)보다 새롭다. (대표 지시)
- A3 1차:2차 비율은 최소 비율이다. 2차 비중 60% 이상이며 30:70처럼 더 치우쳐도 된다. 개수로 바꾸지 않는다. (대표 지시)
- A4 대표가 말한 표현을 재해석하거나 바꾸지 않는다. 있는 그대로 적용한다. (대표 지시)
- A5 대표가 지정한 화면·범위 밖은 바꾸지 않는다. 범위를 넓히려면 먼저 묻는다. (대표 지시)
- A6 새 서비스의 UI·레이아웃·정렬은 Admin MASTER와 같다. 세금도 마스터로 본다. (대표 지시)
- A7 리포트와 콘텐츠에는 근거(법령 우선, 신뢰 사이트 허용)와 날짜를 적는다. 리포트의 편집·UI도 내용만큼 중요하다. (대표 지시)
- A8 문제가 생기면 LESSONS에 쌓고 다음 구현에서 반복하지 않는다. 속도를 중시하고 같은 오류를 반복하지 않는다. (대표 지시)
- A9 "완료"는 실제 화면(진입 → 1차 → 2차 → 결과)을 직접 본 뒤에만 말한다. (LESSONS 1)
- A10 AI 리포트는 세금 패턴(참고 사항)을 따른다. 나중에 서류가 첨부되면 문서 스캔 AI와 OpenAI 결과를 리포트에 반영한다. 지금은 표시만 하고 구현하지 않는다. (대표 지시)
- A11 main 병합과 push는 대표의 명시 승인 후에만 한다. main은 운영 자동배포다. (대표 지시)
- A12 이 문서와 QUESTION_STANDARD.md의 내용을 대표에게 다시 설명하게 하지 않는다. (대표 지시)
- A13 수정 요청이 오면 틀린 부분만 고친다. 전체를 처음부터 다시 리뷰하거나 다시 만들지 않는다. 예: AI 리포트 지적이면 AI 리포트 부분만 고친다. (대표 지시 2026-10-11)

## 질문·선택·표현 (VFBCAI_QUESTION_CHOICE_RULE_LOCK_FINAL.md, 2026-09-27)

- Q1 전체 질문 수는 정하지 않는다. 사건에 필요한 질문 수가 먼저이고 비율은 그 안에서 맞춘다. 비율을 맞추려고 질문을 추가하지 않는다. (§1)
- Q2 선택지는 단답형이 아니다. 선택지 하나가 실제 사건 하나를 설명한다. 1층은 고객이 한 일 또는 일어난 일, 2층은 그 결과·상대 반응·현재 상태다. (§2)
- Q3 1차 질문의 선택지는 모두 2층 구조다. 2차 질문도 기본은 2층이고 꼭 필요할 때만 3층이다. 구조를 채우려고 맥락 없는 내용을 늘리지 않는다. (§2)
- Q4 질문과 선택만으로 끝까지 가면 고객에게 더 묻지 않아도 상황 파악이 끝나야 하며, 선택 결과가 그대로 데이터로 쌓여야 한다. (§2)
- Q5 대상은 베트남어를 모르는 외국인이다. 접수·보완·반려·소명 같은 용어로 판단을 요구하지 않고, 고객이 겪은 행동과 들은 말로 쓴다. (§3)
- Q6 개인화(2차) 질문은 앞 선택을 이어받아 한 단계 더 구체화한다. 같은 사실을 다시 묻지 않는다. (§4)
- Q7 직접 입력 문구는 그대로 고정한다: 위에 내용이 없거나 설명이 필요합니다 → 직접 입력. 문구를 바꾸거나 설명을 덧붙이지 않는다. 직접 입력은 저장 → Profile 반영 → 다음 질문 → 필요 시 재분류 → 결과 영향의 실제 경로여야 한다. 질문 카드 안에 반복해 넣지 않고 흐름 하단에서 한 번 처리한다. (EXPRESSION_MASTER_EXECUTION_RULE §2, HANDOFF K)
- Q8 모르겠습니다·기타 같은 기계적 선택지를 쓰지 않는다. 무엇을 몰랐는지를 상황으로 쓴다. (같은 문서 §2)
- Q9 선택지는 서로 다른 실제 상황을 뜻하고 의미가 겹치지 않는다. 모든 선택지가 같은 다음 질문으로 이어지면 설계가 부족한 것이다. 선택지는 짧게 만드는 것이 목표가 아니다. (같은 문서 §3)
- Q10 한 축은 한 질문에서만 묻는다. 같은 사실을 두 질문에서 다시 묻지 않는다. (LESSONS 7, 같은 문서 §0)
- Q11 제2 사실을 붙이려면 ① 같은 경로의 다른 질문이 이미 묻는 사실이 아니고 ② 판단·다음 행동·위험도를 실제로 바꾸고 ③ 가능한 값을 같은 질문 선택지가 모두 덮어야 한다. (VFBCAI_SECOND_FACT_ATTACHMENT_RULE_v1_1.md)
- Q12 "다음에 무엇을 할 계획인지"만 묻는 질문은 쓰지 않는다. (같은 문서)
- Q13 질문은 목적 → Profile 필드 → 분기 → 결과·판단 → 다음 행동으로 이어져야 한다. 결과와 연결되지 않는 질문은 넣지 않는다. 문서로 확인되는 사실은 질문으로 반복해 받지 않는다. (EXPRESSION_MASTER_EXECUTION_RULE §1)
- Q14 질문 표현만 바꿔서 기존 저장 키·Profile·분기의 데이터 의미가 달라지면 안 된다. (같은 문서 §0)
- Q15 목록형 질문(증거·서류·보완 항목)은 복수 선택, 한 chip은 한 자료 종류다. (같은 문서 §3.1)

## 구조·개발 (VFBCAI_MASTER_HANDOFF_PRINCIPLES_v1.md, MASTER_DEVELOPMENT_SKILL_v1.2)

- D1 이미 구현된 Admin Master와 CASE_01~06을 폐기하거나 다시 설계하지 않는다. 서비스마다 도메인 질문·값·규칙만 Adapter로 붙인다. (HANDOFF §1·§2·§8)
- D2 공통 Master 문제는 한 번 고쳐 모든 서비스에 쓰고, Adapter 문제는 그 서비스만 고친다. 문제가 생기면 공통/Adapter/질문 데이터/QA harness 중 어디 문제인지 먼저 가른다. (HANDOFF §7)
- D3 CASE_07을 임의로 만들지 않는다. CHECK / VERIFY / REGISTER / PROTECT 구조, Master Funnel, DB / API / CRM / Storage / RLS, Signup·기존 Result·확정 Business Logic을 임의로 바꾸지 않는다. (EXPRESSION_MASTER_EXECUTION_RULE §0)
- D4 Phase1과 Phase2는 같은 정보를 반복하지 않고 정보 밀도가 균형을 이룬다. (HANDOFF D·E)
- D5 raw slug를 저장하고 표시 라벨과 분리한다. persistence/restore 후에도 같은 프로필과 질문 상태가 유지된다. (HANDOFF I·J)
- D6 질문 진행 중에는 불필요한 결과·전문가 CTA를 보이지 않는다. (HANDOFF L)
- D7 브라우저 E2E는 실제 UI를 통과해야 한다. harness가 상태를 직접 넣어 통과한 것처럼 만들지 않는다. harness 실패와 제품 실패를 구분한다. (HANDOFF M·N)
- D8 코드 변경 뒤에는 `npx tsc --noEmit`. 증거 없이 PASS / COMPLETE / LOCK이라고 선언하지 않는다. (HANDOFF O·P)
- D9 과거·레거시 자산(옛 엔진, 번역표, 옛 페이지, 폐기 초안)을 새 작업에 끌어오지 않는다. Admin MASTER는 읽기 전용 기준선이며 수정하지 않고 가져다 쓰기만 한다. admin, tax, real-estate는 수정하지 않는다. 공용 등록 파일은 추가만 한다. (대표 지시, LESSONS 10)
- D10 마스터 문서는 새로 만들거나 고치지 않는다. 현재 상태 그대로 둔다. (RULE_LOCK §0)
- D11 운영 DB에 연결된 개발 서버에서는 저장·가입 단계를 누르지 않는다. (LESSONS 14)

## 변경 절차

- 이 문서와 QUESTION_STANDARD.md를 바꾸려면 대표 승인이 먼저 필요하다.
- 승인 뒤 커밋 메시지에 `ACE-APPROVED: <사유>` 줄을 넣고, `docs/master/.standards.sha256`을 같이 갱신한다.
- 대표 승인 없이 Cursor나 Claude가 임의로 바꾸지 않는다. verify의 standards-lock 검사와 commit-msg hook이 막는다.
